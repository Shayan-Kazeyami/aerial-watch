# Canonical assets: required immutable release derivation guard
The four exact canonical paths use unchanged retained release87a bytes. Do not change their intended geometry while leaving the old owner mapping. Retain local copies and declared owner trees for rollback and closure.
Use identity-gate.mjs before writing a new sealed manifest or receipt; derive.py is the tested reference integration. It reads the prospective routing module map, checks manifest identities, and hashes intended overlay/base bytes and retained owner's real bytes. The parameters are prospective manifest JSON, prospective assembly-asset-routing.js, staged overlay root, baseline release root, and retained releases root.
A geometry edit must explicitly remove or repoint its canonical pin. Never synthesize a historical owner identity only from new intended metadata. identity-negative.mjs tests simultaneous intended bytes + local/reference metadata mutation against unchanged owner bytes and must fail closed.
Keep post-materialization verify.mjs and full seal verification, including receipt counts and byte totals, plus rawfallback/closure and cold/warm/transition behavior. Manual custom derivations must call the same helper; these files do not configure branch protection or alter GitHub Pages deployment.
